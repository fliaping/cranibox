# 客户端实机验证环境

安装包验证不要求在每台机器安装 Rust、Node.js 或完整源码。先记录系统版本、CPU 架构和桌面类型，提供匹配的安装包；需要现场编译或调试时再准备工具链。CI 编译、浏览器 IPC 模拟和 Linux 集成测试均不能替代下面的实机验收。

## 接入条件

自动检查需要 SSH 用户名、端口和已配置的密钥登录；Windows 原生与 WSL2 的 SSH 必须分别注明。只提供 IP 不能确定进入的是宿主还是子系统。macOS 开启“远程登录”后可以检查文件和进程，但测试窗口、托盘与系统权限仍需该用户已登录桌面。

初次只检查版本、会话、现有依赖和端口，不安装系统组件、不更换桌面、不改变现有容器和 VPN。确需安装时使用项目向导中可检查的安装计划；Tailscale 登录、系统授权、重启及签名确认由现场用户处理。不要在 issue、日志或聊天中粘贴私钥、密码或节点 Token。

| 环境 | 最低准备 | 附加准备与边界 |
| --- | --- | --- |
| Windows 原生 | 目标用户已登录桌面；匹配架构的安装包；可运行客户端 | 检查 WebView2；测试托盘、自启动、窗口关闭后驻留、原生 PTY。当前 VNC 自动托管尚未支持 Windows，桌面访问先连接用户选择的现有 VNC 服务 |
| Windows WSL2 | 可登录的 Linux 发行版；单独配置目录与 NodeID | 测 Linux 节点、终端、后台执行和容器空间。WSL2 验证通过不能当成 Windows 原生客户端通过；WSLg/X11 的画面也不是 Windows 宿主桌面 |
| Linux 无桌面 | SSH；匹配架构和系统运行库的 CLI 二进制 | 可测组网、消息、任务、项目和后台执行；不能据此判定托盘、屏幕共享通过 |
| Linux 有桌面 | 上述环境；目标用户的图形登录会话 | 记录 X11/Wayland 与桌面名称。托管 x11vnc 需要 X11；托管 wayvnc 需要兼容 wlroots 的会话和 wayvnc ≥0.8。GNOME/KDE/Weston 走现有兼容 VNC 服务，不能直接套用 wayvnc。托盘需桌面支持 AppIndicator；检查 GTK/WebKit 运行库 |
| macOS | SSH；Intel/Apple Silicon 架构；目标用户已登录桌面；对应安装包 | 测托盘、自启动、原生 PTY。当前包未配置签名/公证，需要用户确认安装；桌面访问先配置系统屏幕共享或兼容 VNC 服务，验证其认证方式。需要系统弹窗时由目标用户明确授权 |

每个原生系统和 WSL2 都是独立节点，不能共用同一个持久 NodeID 配置目录。测试节点与日常使用节点也应分开保存配置。

## 可选能力的环境

- **同网段直连**：测试入口能够访问目标节点配置的监听端口；节点能够通过已授权路径相互访问。SSH 只用于部署与诊断，不作为产品数据通道。
- **EasyTier / Tailscale**：先检查现有安装和网络配置。分别验证直连、中继及断线恢复，再验证两者同时存在。Tailscale 使用用户自己的 tailnet 和 ACL；测试报告不得把只在局域网成功写成公网穿透成功。
- **虚拟空间**：使用可操作的 Docker 兼容引擎。Windows 可使用 WSL2 中的引擎或现有 Docker Desktop；macOS 可使用现有 OrbStack、Colima 或 Docker Desktop；Linux 使用现有 Docker。确认可用磁盘、镜像来源和测试容器名称，避免接管已有容器。
- **远程桌面**：每台待共享机器需要真实图形会话和 VNC 提供者；客户端先连接本机回环端口，再由授权节点转发。分别记录认证、首帧、键盘、鼠标、缩放、断线重连与撤权。无人登录时的画面、锁屏与多显示器单独记录。
- **Agent**：后台进程验收先使用只写临时目录的测试程序，不需要模型账户。实际 harness 交互再使用本机已经配置好的 CLI 和凭据，不能把进程退出码当成协作任务完成报告。

## 验收顺序

1. 在三个原生系统安装对应客户端；WSL2 额外作为独立 Linux 节点。记录版本、架构、NodeID，确认没有启动重复所有者。
2. 验证本机终端、后台执行、关闭窗口驻留、托盘找回、退出确认和登录自启动；休眠、网络切换及重启后检查状态是否准确。
3. 授权并连接所有目标。关闭 Workspace 中继后，确认已有对等路径仍能执行授权能力；再测试仅中继可达及恢复直连的情况。
4. 验证项目目录、确认后的工作文件复制、消息、任务领取/提问/结果；断网与重启后重复请求不能重复执行。
5. 远程桌面做 Windows↔Linux、Windows↔macOS、Linux↔macOS 六个方向；浏览器入口与 Tauri 查看器都测试。WSL2 不代替 Windows 桌面目标。
6. 使用独立名称创建、停止、重新启动、删除测试虚拟空间，检查数据保留规则与容器节点自动接入。

每条结果记录版本、两端 NodeID、实际网络路径、操作、预期、结果及脱敏证据。状态区分“通过”“失败”“环境不具备”“尚未实现”，不以编译通过代替可用性结论。
