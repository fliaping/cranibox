# 对等节点组网与远程能力设计

设计日期：2026-10-14；实现进度更新：2026-10-18。状态：整体方案仍在交付中。已实现持久 Ed25519 节点身份（新 NodeID 由公钥派生，旧随机 ID 由签名绑定）、只存加盐摘要的签名授权、Noise IK 节点间端到端加密（含 WebSocket 数据帧）与配对码核对（[节点身份与端到端加密](node-identity-and-e2e.md)）、目标本地授权与独立直连 HTTP/WebSocket（[配置与边界](direct-node-peers.md)）、[VNC/noVNC 桌面](remote-desktops.md)、[虚拟空间](virtual-spaces.md)，以及 Web/Tauri 共用的 [EasyTier 用户态托管、节点发现和授权连接、系统 Tailscale 状态与登录](device-networks.md)。EasyTier 已支持 Workspace 地址加短期单次邀请引导，以及多个入网地址；自动多路径与目录同步尚未实现。旧网关继续兼容，实际行为见[托盘客户端与 Agent 设备组网](node-desktop-and-device-mesh.md)。下文的 v2 API 仍是设计目标；公钥身份以 node-identity-and-e2e.md 描述的实现为准。

维护者已明确先满足自己的日常多设备使用。产品主线、项目/Agent 会话模型、消息协作与迁移边界见[多设备项目与 Agent 工作空间](distributed-agent-workspace-design.md)。先形成统一项目视图、对等连接、跨机 Agent 协作与手动迁移闭环，再扩展远程桌面等能力；本文保留底层组网和能力接入细节。

## 1. 目标与已确定的选择

每台 Windows、macOS、Linux 设备都是同等身份的 Cranibox 节点。每个节点上的 Agent 可以调用其他已授权节点的命令、终端、Computer Use、Browser Use 和远程桌面能力。Workspace 提供浏览器控制台、入网入口和可选中继，不成为执行或授权必须在线的中心。

| 项目 | 选择 |
| --- | --- |
| 自部署组网 | EasyTier，提供对等连接、NAT 穿透和中继 |
| 其他组网 | 支持官方 Tailscale 登录，与 EasyTier 同时运行 |
| 首次接入 | 一个 Workspace HTTPS 地址和入网 Token；客户端完成其余配置 |
| 应用寻址 | 稳定 NodeID + ServiceID；用户无需分配、填写虚拟 IP |
| 权限 | 目标节点本地验证；加入网络不等于获得执行权限 |
| 节点身份 | Docker、桌面和无界面部署使用同一 NodeID 与授权模型，部署形态不产生主从关系 |
| 客户端 | 独立 Rust 节点引擎；Tauri 2 承载共享 React 控制台和系统托盘 |
| Web 控制台 | 启用 Web 角色的任意节点提供 Rust HTTP/WebSocket + 同一 React 控制台 |
| 视图与入口 | 同一授权主体看到同步收敛的设备、项目、会话与任务视图；Tauri 接入本机，浏览器选择可达 Web 节点，无全网主节点 |
| Web 远程桌面 | noVNC + VNC/RFB；Rust 管理接入和转接 |
| 客户端桌面后端 | 随安装包提供可用的 VNC 组件，或接入系统现有服务；按平台选择 |
| Linux 备选 | 保留 Selkies，尤其是当前 KDE/Wayland 环境 |
| RustDesk | 移出默认依赖；以后确有需求时作为外部兼容适配器评估 |

已有虚拟组网负责设备连通，远程桌面无需再部署一套 RustDesk ID 服务、协调和中继系统。VNC 覆盖当前浏览器查看、键鼠操控的目标；高清动态视频、高延迟链路体验需另做测试，不能仅凭组件数量断言 VNC 的 CPU 或带宽一定更低。

客户端的“内置 VNC”指一次安装、统一配置、生命周期由节点管理。第一阶段不要求把第三方 VNC 实现静态链接进 Rust 主程序，也不要求第三方桌面后端使用 Rust。

## 2. 现有实现与迁移边界

现有节点使用 /ws/nodes/{id} 向 Workspace 建立出站 WebSocket。/api/v1/mesh/* 和服务端 mesh_groups 决定节点间的命令访问，命令仍经 Workspace 转发。填写 Tailscale 地址只改变连接 Workspace 的网络路径，尚未让节点直接互访。

当前 Tauri 客户端的 React 页面通过 Tauri IPC 调用 Rust；生产界面加载打包的静态资源，不需要额外启动一个本地 HTTP Web 服务器。开发时使用的 Vite 服务不属于发布后的常驻服务。

节点 Rust 引擎在窗口之外运行；窗口关闭后留在托盘。原生 PTY 由节点持有，网络断开可以重新附着；客户端退出、进程重启或系统重启不能恢复之前的 Shell。继续保持客户端不包含 herdr。

迁移保留现有 v1 接口作为兼容通道。新节点应区分“对等连接”“EasyTier/Tailscale 中继”“旧版 Workspace 命令网关”，不能将 v1 转发标成 P2P。本文后续 v2 API、模块和 MCP 工具名称都是拟议接口。

## 3. 整体架构

~~~mermaid

    AU[Tauri / React / 托盘] -->|IPC| AR
    AR --> AC[Shell / Computer Use / Browser Use / VNC 后端]
  end
  subgraph B[节点 B]
    BA[本机 Agent / MCP] --> BR[Rust 节点引擎与本地授权]
    BU[Tauri / React / 托盘] -->|IPC| BR
    BR --> BC[Shell / Computer Use / Browser Use / VNC 后端]
  end
  subgraph C[Docker 节点 C]
    CU[浏览器 / 共享 React 控制台] -->|HTTP / WebSocket| CR[Rust 节点引擎与本地授权]

    CR --> CG[可选 Web 网关 / 引导 / 中继角色]
  end

  ET -.-> WR[任意已配置的引导 / 中继节点]
~~~

划分四层：

1. 身份与信任：NodeID、网络成员资格、目标节点授权和撤销。
2. 网络传输：EasyTier、Tailscale，以及必要的已有 v1 兼容路径。
3. 能力服务：任务、PTY、注册端口、Computer Use、Browser Use、桌面附件。
4. 展示与入口：本机 MCP/CLI、Tauri 客户端、Workspace 浏览器页面。

网络路径切换不改变节点身份，也不扩大权限。服务端与客户端仍是不同应用，通过共享 Rust 库复用能力，不合成一个必须同时运行的程序。

### 3.1 Docker 部署也是普通节点

Docker 中的 Workspace 使用与桌面客户端相同的节点核心、NodeID、能力协议与目标授权模型。默认额外启用浏览器入口、引导和中继角色，适合持续在线，但它不因此成为其他节点的上级，也不独占节点目录或权限签发。

部署形态、能力和角色分开记录：container/desktop/headless 是运行环境；web-gateway/bootstrap/relay 是可选职责；命令、浏览器与桌面是可调用能力。普通节点可以启用合适的角色，Docker 节点也可以只提供自身能力。

Docker 节点的私钥和 NodeID 放在独立持久化卷中，不写进镜像。重建同一实例复用原身份；新建副本生成新身份，不能让多个活跃容器共用同一私钥。容器与宿主机是不同执行边界；容器节点只能发布实际可用且明确授权的能力，不能默认将容器命令当作宿主机命令。

### 3.2 同一套界面，连接任意入口

抽取共享 React 控制台，统一设备列表、目标切换、Agent、服务、任务、终端、桌面、浏览器和网络页面。Tauri 与浏览器复用路由、组件、类型和视图模型，只替换连接适配器：

| 入口 | 界面如何接入 | 如何访问目标 |
| --- | --- | --- |
| 本机 Tauri | 共享 React → Tauri IPC → 本机 Rust 节点 | 本机引擎按 NodeID 路由到目标，目标验证授权 |
| 浏览器 | 同一 React → HTTPS/WSS → 任意可达且启用 Web 的节点 | 接入节点作为已授权网关转接到目标 |
| CLI/MCP | 当前用户的本机 IPC → 本机 Rust 节点 | 使用同一目录与能力路由，保留 Agent 主体权限 |

“当前接入节点”和“当前操作目标”是两个独立状态。浏览器连接 Docker 节点 C，仍可选择 A 的终端或 B 的桌面；打开 A 的 Tauri，也能看到授权范围内的 C。界面不要求用户先找“主节点”。本机托盘、自启动和权限提示作为平台设置，业务页面保持一致。

统一视图以同一用户/Agent 主体和有效授权范围为前提，不将连接入口的管理员身份代替当前用户。跨入口需要可验证的同一主体或目标认可的网关委托；系统账号名或显示名称不能单独证明身份。来源节点有不同授权时，可操作范围本来就可能不同，不能为了页面相同泄露未授权资源。

同一授权主体在同步完成后看到相同的设备与能力清单；在线状态、路径时延和本机标记允许随观察位置不同。网络分区时显示最后同步时间、不可达或未知，不宣称所有页面在同一瞬间完全相同。

Tauri 默认接入本机，避免依赖远端入口。浏览器可以使用默认 Docker HTTPS 地址，也可切换其他已配置的 Web 节点；新入口重新验证用户和目标授权，按目标持有的 ID 查询/附着任务。单一公网域名自动切换入口是额外的反向代理/负载均衡部署能力；节点对等和选主都不会自动让离线 URL 恢复。

### 3.3 同步目录，保留状态的所有者

每个节点维护本地目录副本，通过认证后的节点通信交换摘要与更新；重新连接时补齐缺失记录。首期采用各记录明确所有者的签名快照/增量与周期校验，不引入全网共享、任意节点可写的数据库。

| 数据 | 权威来源与同步方式 |
| --- | --- |
| 节点描述、地址、能力清单 | 对应节点签名，按所有者版本同步 |
| 服务配置、授权与撤销 | 目标节点或它明确认可的签发者；按调用者范围提供，不能由目录缓存覆盖 |
| 在线状态与路径健康 | 各接入节点的实时观察与带期限公告；不是全网一致的永久事实 |
| 任务状态、PTY、桌面附件 | 目标节点持有；目录可缓存摘要，操作前直接查询目标 |
| 分组标签与界面偏好 | 明确用户/配置所有者；权限相关分组不通过普通标签合并授予能力 |

每条所有者记录带 NodeID、记录类型、版本和签名。接收方只接受认可所有者的有效更新，保留版本高水位与删除信息，避免断线节点重新发布旧快照导致已删除记录复活；不按设备时钟决定授权覆盖关系。主体或密钥变更要走显式认可的迁移流程。

签名目录仍只是发现信息。执行前目标检查当前策略；本地缓存显示“允许”但目标已撤销时，目标拒绝并触发视图刷新。秘密、VNC 密码、浏览器凭据和完整任务输出不放进目录广播。

### 3.4 默认无需选主

界面统一、目录收敛、目标节点本地执行和授权不需要全网选主。任何合适节点都可提供 Web 入口，关闭某个入口不改变其他节点的地位；节点在分区内继续执行自身能够验证和完成的操作。

以后若增加“一个全网定时任务只能被一个调度器触发”“共享配置必须按全局顺序提交”等要求，再为该项协调能力引入明确的主节点/共识机制。它只负责对应服务，不成为所有命令、桌面和网络数据的必经入口。

使用 Raft 等共识时，需要确定稳定的投票成员与多数派可用性 [R12]，不把休眠或经常离线的所有终端都作为默认投票节点。少数分区无法继续提交受共识保护的写入；仅比较 NodeID 或心跳选出“最大节点”不能保证分区中只有一个有效调度方，执行端还需验证协调服务的执行资格。首期不承担这项额外依赖。

## 4. 节点身份、入网与无中心运行

### 4.1 稳定身份

节点首次启动生成本机身份密钥，NodeID 从公钥推导；使用成熟的 Ed25519、TLS 实现，不设计自有加密算法。节点能力连接采用相互认证，证书公钥与已信任 NodeID 绑定；EasyTier 或 Tailscale 地址只是可替换的路由信息。

同一设备同时连接两个网络时，只显示一个节点、两条候选路径。网络中的 PeerID、Tailscale 设备 ID 与 Cranibox NodeID 分开保存；映射由节点签名，不能按 IP 或显示名称认定身份。

身份私钥与后端密码优先使用系统凭据存储；无界面环境使用当前用户的私有状态目录。迁移现有 node.token 不会自动把所有同组设备升级为可执行全部能力的可信对等节点。

### 4.2 一个地址和 Token 接入

拟议引导流程：

1. 客户端生成身份，在界面输入 Workspace HTTPS 地址和入网 Token。
2. 调用 /api/v2/network/bootstrap，验证服务端 TLS 和返回的网络信任信息。
3. 获取 NetworkID、可用引导节点、中继入口、EasyTier 凭据配置和网络成员描述。
4. 由 Rust 启动受管 EasyTier，验证对等连接，缓存已验证的其他节点地址与签名描述。
5. 目标设备所有者设置允许哪些节点使用哪些能力；默认仅入网，拒绝跨设备执行。

入网 Token 是短期邀请，建议默认 15 分钟、一次使用，并允许显式配置有效期与使用次数。它不作为 VNC 密码、长期节点私钥或全网共享的执行凭据，不写入 URL、日志和进程参数。

EasyTier 原生协议的认证与 Cranibox 引导 API 的 Bearer Token 是不同层，不能把现有 /ws/nodes/{id} 当成 EasyTier 接口。Workspace 会提供独立的 EasyTier 协议监听和受控反向代理入口；443/WSS 路径兼容性须用固定版本验证后发布。

### 4.3 Workspace 不在线时

已入网节点保存网络配置、可信公钥、目标节点授权和多个引导地址，可直接访问其他可达节点；执行和授权不查询 Workspace。支持向其他已授权引导节点连接，或使用由有邀请权限的成员签发的邀请入网。

网络成员签发权可委托给多个节点，不绑定某个 Workspace 实例。设备所有者始终可在本地配对可信节点、修改本地能力策略；不要求向中心申请每次运行许可。

首次仅持有某个已离线服务端的地址和不透明 Token，且从未取得其他成员信息时，不能凭空发现网络。此时需要其他可达成员的邀请/地址。所有直连路径失败且唯一中继离线时，也不可能继续互联。这些情况要明确报错，不能承诺任何网络条件下服务端离线都能连接。

## 5. EasyTier 集成

EasyTier 官方将节点设计为对等角色，任一可达成员可成为引导入口，支持穿透与中继 [R1]。首期采用固定版本 easytier-core 受管进程，不将上游内部模块直接当作稳定 Rust SDK。

Rust 负责生成配置、启动、健康检查、退出与重启、版本校验和状态转换。更新按发布清单固定版本与校验和，并支持回滚；程序和长期配置不在启动时临时下载。

### 5.1 用户看到端口与节点，内部允许网络地址

用户填写 NodeID/设备名称和服务，不手工管理虚拟 IP。EasyTier 仍可能在内部使用 overlay IP；“用户无需虚拟 IP”不等于上游完全没有 IP 地址。

优先验证无 TUN 的用户态 TCP、SOCKS 和端口转发路径 [R2]，覆盖从源节点 Rust 引擎到目标节点能力网关的双向连接。验证范围包括目标侧入站交付，不能只验证源端能连接 SOCKS。若固定发布版无法完整实现，需明确说明需要 TUN/权限的模式，不能将开发分支功能作为默认已支持能力。

用户态模式首期只要求 TCP 能力流；UDP 原生应用与全局 VPN 属于独立扩展。内置 SOCKS/RPC 入口必须显式绑定回环或受控接口，不直接使用会绑定 0.0.0.0 的 CLI 简写配置 [R2]。应用级流只能到已注册服务；不向 Agent 开放任意网络 SOCKS 代理。

### 5.2 成员资格与撤销

优先评估上游 secure-mode / credential 对每个设备独立签发、撤销的支持，确认固定发布版的接口和行为后启用 [R2]。共享 network_secret 仅用于验证组网；共享秘密不能单独撤销某个已持有秘密的设备。

即使底层暂时使用共享网络凭据，目标节点仍必须验证 Cranibox 身份和能力权限。撤销应用权限立即阻断能力访问；底层网络移除需执行对应提供者支持的撤销/密钥轮换，界面区分两者。

### 5.3 引导、中继与穿透

Workspace 默认可管理一个 EasyTier 实例，承担入网引导和允许的中继。用户可配置其他中继节点，避免唯一公网服务器成为连通性的单点；普通电池设备不默认转发其他设备的大流量。

穿透候选信息采用 EasyTier 原生发现/协调机制，按需配置真实 STUN 服务。HTTPS/WSS 接口提供配置和注册信息，不等于它本身提供 UDP STUN。部署只开放选定的监听端口；UDP 被禁用时允许降级 TCP/WSS，界面显示实际经过中继。

## 6. Tailscale 并行集成与路径选择

使用官方 tailscaled 与 CLI，复用现有容器 userspace 集成；桌面端支持已有系统 Tailscale，以及明确选择的受管安装模式。Tauri 显示登录链接、账号与网络状态，不持有账号密码，不自行实现 Tailscale 控制协议。

登录按官方账号流程进行，状态通过官方机器可读接口取得。启用 Tailscale 不关闭 EasyTier。Tailnet 成员资格和 ACL 只决定网络能否连接，Cranibox 目标节点权限继续生效。

Tailscale 仍有集中式协调服务，数据通常直连，不能称为完全无中心控制平面。官方说明协调服务离线时已有节点可使用缓存的密钥和策略通信，但设备加入、策略更新和密钥续期受影响 [R3]。

路径选择按用户偏好、可达性、时延与中继成本排序，在 EasyTier 直连、Tailscale 直连和允许的中继间切换。网络提供者本身选择的直连/中继状态要如实显示。

网络切换会断开已有 TCP 流；不能承诺透明迁移正在运行的 VNC 连接或任意端口流。新连接选择健康路径，终端和任务按目标节点持有的会话 ID 重新附着/查询。命令、点击、键入等有副作用请求不自动重新提交。

## 7. 目标节点本地授权

目标节点定义允许的来源 NodeID、Agent 身份、服务、动作、资源范围和有效期；在本地验证并记录审计。每次建立连接和提交操作检查权限，长连接按租约重新检查；目标撤销后主动结束对应数据流。

网络组用于发现和成员管理，默认不赋予执行权。示例授权是“笔记本上的指定 Agent 可在开发机的项目目录执行命令并附着自己的终端”，或“该节点可查看桌面，但不能输入”；不是授予整个网络任意机器控制权。

使用目标所有者本地策略或目标认可的受限签发者发放能力授权。Workspace Web 用户需要目标允许的用户/代理身份：目标显式信任某个 Web 网关代表哪些用户、允许哪些操作。Workspace 管理员不会因为能够邀请成员就自动获得所有设备 Shell 或桌面控制权。

本机 Agent 通过当前用户受限的 Unix Socket / Windows Named Pipe 接入节点引擎，MCP 进程复用常驻引擎，不另起托盘或第二套组网进程。将不同 Agent 作为独立主体时，必须使用目标可验证的主体凭据或受信任本机代理证明，不能相信请求里自填的 Agent 名称。

撤销在收到并应用该撤销的目标节点立即生效；离线节点不可能即时知道尚未送达的全网撤销。使用签名策略更新、授权有效期和租约限制传播延迟，过期授权默认拒绝。界面显示撤销是否送达，而不是把中心记录删除当作所有设备已完成撤销。

## 8. 能力目录与 Agent 调用

节点发布签名、带期限的能力描述；通过对等发现分发，Workspace 可以缓存，但不是唯一目录。显示名称只是展示信息，授权和调用使用 NodeID、ServiceID 和声明版本。

| 能力 | 目标节点负责 | 必须保留的边界 |
| --- | --- | --- |
| 命令 | 启动、输出、超时、取消、任务状态 | 目标用户权限，目录/动作策略，禁止断线自动重放 |
| 终端 | 原生 PTY、会话列表、附着和结束 | Shell 由目标持有，客户端进程退出后不能恢复 |
| 注册端口 | 服务发现与 TCP 字节流 | 仅授权服务，默认本地监听，不接受任意目标地址 |
| Computer Use | 屏幕、鼠标、键盘、窗口及显示器 | 实际驱动可用性、OS 权限、控制租约、紧急停止 |
| Browser Use | 受管浏览器配置、标签页与自动化 | 按浏览器配置授权，不公开裸 CDP 或任意用户浏览器 |
| 远程桌面 | VNC/Selkies 会话与附件 | 查看/控制权限由目标真正执行，关闭页面不退出桌面 |

拟议 MCP 增加 nodes、capabilities、exec、jobs、terminal、computer、browser、ports 等入口，采用统一目标参数；工具枚举只展示调用者已授权的能力。版本协商不支持时明确失败，不猜测旧客户端可以执行新能力。

目标节点维护任务 ID、请求去重记录与终端 ID。重连首先查询原任务；“发送成功但响应丢失”不能自动产生第二次执行。网络重连不终止托管 Shell，进程/系统重启不承诺恢复仍在运行的内存会话。

## 9. Computer Use 与 Browser Use

远程桌面查看器不是 Computer Use 驱动。VNC 提供像素与键鼠传输，但不会自动提供窗口识别、无障碍树、Agent 工具或浏览器标签页管理。

当前 Linux/Selkies 桌面继续使用已集成的 desktop bridge。Windows/macOS/X11 按平台验证原生驱动或 cua-driver，KDE/Wayland 按已有[驱动评估](cua-driver-assessment.md)保留适配；不能把协议跨平台等同于完整桌面能力跨平台。

Browser Use 经本机受管浏览器适配器执行；CDP 等驱动入口只监听本机或私有受控接口。网络中任意节点不能直接访问全部浏览器配置，不能因为开启了桌面查看就取得浏览器登录态。

同一桌面的 Agent 输入与人工控制共享目标节点输入租约。控制会话只允许一个有效控制方，其他调用者可在后端确实支持时仅查看；需要人工接管时暂停 Agent 输入。租约撤销必须关闭控制连接/撤销驱动权限，不能只禁用网页按钮。紧急停止持久化，重连或驱动重启后保持暂停。

节点清单明确显示未安装、等待权限、无登录会话、无显示器、仅查看、暂停等状态。缺失底层权限时不能显示为“可控制”。

## 10. 注册端口与服务映射

对用户提供“127.0.0.1:18080 → 开发机 / 项目 Web 服务”这类映射。目标先注册 ServiceID 到本机端口，来源按 NodeID/ServiceID 创建映射。默认不能传入任意 host:port 让网关连接，以避免网关成为未授权的网络代理。

注册服务按类别保留应用权限：VNC、CDP、Computer Use 不能作为无认证 TCP 端口公开。映射流先通过目标的身份认证和授权，再接到本地后端。普通服务可由设备所有者显式注册和授权。

本地监听默认回环，外部绑定需明确设置；记录映射的拥有者、目标、有效期与活跃连接。实现缓冲上限、背压、连接数限制和取消，防止断线积压耗尽内存。

映射监听可以保留等待网络恢复，但已经断开的 TCP 连接由应用重连；不伪装成连接从未中断。内置桌面转接使用同一服务路由层，无需额外的桌面网络身份或端口体系。

## 11. 内置 VNC 的实际方案

### 11.1 分层与安装体验

推荐“Rust 节点主程序 + 受管桌面后端 + React/noVNC 查看器”。节点安装包携带本平台可分发的后端，Rust 负责配置、启动、健康检查、端口隔离和停止；用户在 Cranibox 内启用桌面，不需要再管理一个独立 VNC 软件界面。

~~~mermaid
flowchart LR
  UI[Tauri React 界面] -->|IPC / 权限设置| N[Rust 节点引擎]
  N --> P[VNC 提供者适配器]
  P --> V[受管 VNC 进程或系统屏幕共享]
  V --> D[当前登录桌面]
  N --> G[授权后的桌面服务流]
  G --> M[EasyTier / Tailscale]
~~~

第一阶段采用成熟后端；不用重新实现 RFB 编码、平台捕获、输入和安全桌面支持。LibVNCServer 可通过 FFI 实现进程内协议服务，但它只解决 VNC/RFB 部分，仍需编写各 OS 的屏幕采集与输入回调；其 GPL 授权也需要纳入组合和分发方式评估 [R7]。因此不以“所有平台单个纯 Rust 二进制内置完整 VNC”作为首期目标。

### 11.2 平台选择

| 目标平台 | 首期提供者方向 | 安装与权限 | 限制/回退 |
| --- | --- | --- | --- |
| Windows | 随包提供经过兼容测试的 VNC 服务端；优先验证 UltraVNC 用户会话模式 | Rust 管理后台进程；登录前/提权界面另评估系统服务 | UltraVNC 服务端是 Windows 专用，不能作为三平台公共后端 [R8] |
| macOS | 接入系统屏幕共享/远程管理的 VNC 兼容模式 | 客户端引导用户启用系统功能及所需权限；不复制 Apple 系统服务进安装包 | 先验证 noVNC 安全类型与当前 macOS 兼容性；自带非系统后端另做采集/输入适配 [R6] |
| Linux X11 | 受管 x11vnc 共享当前桌面；虚拟桌面另选 TigerVNC | 访问正确的 DISPLAY、授权文件和用户会话 | 共享物理桌面与新建虚拟桌面是不同能力，不自动替换 |
| Linux wlroots Wayland | 评估受管 wayvnc | 依赖 compositor 支持和当前会话 | wayvnc 不支持 GNOME/KDE/Weston [R9] |
| 当前 KDE/Wayland Workspace | 保留已集成 Selkies 和 desktop bridge | 复用当前桌面与输入后端 | 不为了统一名称强行换成不兼容的 VNC；界面显示 Selkies 提供者 |

“VNC 支持跨平台”指协议与查看器可互通，不代表有一个现成、统一、无权限要求的桌面服务端。macOS 第一阶段属于客户端集成系统服务，而非随包携带同一个 VNC 进程。安装验收前不能宣称三平台完全相同的开箱即用体验。

### 11.3 生命周期与资源

节点引擎与组网保持常驻。首次允许远程桌面时准备后端，打开会话时启动需要的捕获/编码；支持显式开启持续桌面共享。对于不能按连接停止捕获的后端，以实际可用配置为准，不承诺不存在其常驻开销。

受管进程默认与当前登录用户绑定，窗口关闭不终止；主动退出客户端时按拥有关系清理。系统自带或用户独立安装的服务由节点接入，不在客户端退出时擅自停止。进程异常可有限重启，权限丢失或配置错误转为故障状态，不无限循环启动。

登录自启动与登录前常驻服务分开设计。首期继续是用户登录后启动；Windows Service、launchd 或 systemd 系统级安装只在需要无人值守且完成真实 OS 权限测试时提供。不能用系统服务身份直接绕过桌面会话隔离、macOS 权限或 Windows UAC。

锁屏、用户切换、多显示器、无显示器和提权窗口分别验收。后台节点在线不等于桌面一定可查看；OS 限制时返回可识别状态。

## 12. Web 与 Tauri 的远程桌面接入

Web 前端使用 noVNC 的 RFB 模块封装 React 查看器；它要求 WebSocket 或 WebSocket 到 TCP 的转接 [R5]。现有 Rust 服务实现二进制 WSS 流到节点桌面服务的转接，不必增加 Python websockify 常驻进程。

~~~mermaid
sequenceDiagram
  participant B as 浏览器 React/noVNC
  participant W as Workspace Rust Web 网关
  participant N as 目标 Rust 节点
  participant V as 目标本机 VNC
  B->>W: 创建指定节点/桌面会话
  W->>N: 节点认证 + 被允许的用户/代理授权
  N->>N: 验证权限、后端状态与控制租约
  N-->>W: 允许的会话与附件标识
  B->>W: 同源 WSS 附着
  W->>N: 认证后的能力流
  N->>V: 本机 RFB 连接
  B->>W: RFB 输入流
  W->>N: 转接授权流
  N->>V: 输入交付
  V-->>N: 桌面更新
  N-->>W: 转接桌面流
  W-->>B: noVNC 渲染
~~~

拟议浏览器接口是 POST /api/v2/desktop/sessions 和 /ws/v2/desktop/sessions/{session_id}。会话绑定用户、目标 NodeID、ServiceID 和权限，具有短期、一次附着凭据；session_id 本身不是授权凭据。WebSocket 使用受保护的同源会话，验证 Origin，禁止客户端提供任意 VNC 主机与端口。

Workspace 作为浏览器网关会接触桌面数据，必须由目标授权。浏览器到 Workspace 的 TLS 与 Workspace 到节点的相互认证不是“浏览器到目标全程网关不可解密”；节点之间能力流可以使用应用层 TLS，底层网络中继不解密其内容。

Tauri 可复用 React/noVNC 查看器，由本机 Rust 入口经组网直达目标，不依赖 Workspace Web 网关。若 WebView 需要 WebSocket 回环桥，按桌面会话创建受限入口，由 Tauri IPC 完成授权，限制 Origin、连接数和有效期；这不要求客户端默认运行一个对公网开放的完整 Web 控制台。

Tauri 提供共享控制台和本机查看入口。某个 Workspace/Web 网关离线时，它原本托管的网页和网关不可访问；用户可使用本机 Tauri/MCP/CLI，或切换另一个已启用 Web 的节点。每个节点可按需启用浏览器入口，但默认不为桌面客户端开放公网 HTTP 服务。

VNC 后端默认绑定回环或提供者可限制的受控接口，不把 5900 直接暴露公网。系统服务不能绑定回环时，要使用它支持的访问限制、专用密码和网络规则，并明确其额外访问面。RFB 密码与节点身份/入网 Token 分离，在目标端私有存储。

透明 RFB 转接不会自动代替 VNC 密码握手：如 noVNC 需要后端密码，授权后通过 TLS、禁止缓存的会话响应交付到查看器内存，不能拼进页面 URL/日志/持久化浏览器存储。后续只有实现并验证了 RFB 认证代理，才可以宣称密码完全不交付查看器。

noVNC 的 viewOnly 只是客户端不发送输入 [R5]，不是安全边界。desktop.view 授权只有在目标使用专用只读凭据、禁用输入的会话或可靠协议过滤时才能成立。后端不具备此能力时不发布“安全只读”能力；前端禁用键盘不能取代目标校验。控制租约撤销会在目标关闭 RFB 流。

关闭查看器只释放附件和控制租约，不关闭 OS 桌面或用户应用。重连建立新的 RFB 连接，桌面继续存在；是否保留虚拟桌面进程由提供者明确管理。通用 VNC 不自动保证音频、文件传输或全部剪贴板扩展；浏览器剪贴板、IME、触屏操作、缩放和分辨率变化需逐项验收。

Linux Selkies 在同一桌面入口作为独立提供者。当前上游默认 WebSocket，WebRTC 是可选传输 [R10]；不把 Selkies 当作 VNC 后端，也不为其额外建立第二套节点身份。

## 13. 可选服务端职责

Docker Workspace 是启用较多常驻角色的普通节点，可同时提供：

- React 浏览器控制台，以及通过目标授权的命令、终端和桌面网关。
- 入网邀请、引导配置和签名节点目录缓存。
- 受管 EasyTier 引导/中继，以及穿透所需信息的配置入口。
- 组网状态、授权送达状态、节点健康和版本管理。
- 已有 Workspace 本机服务与 Agent 能力，身份与其他节点相同。

上述角色也可由具备条件的其他节点启用。浏览器接入某个节点只选择了当前网关，没有给它全网主节点身份；节点目录由成员同步，目标仍负责最终授权与执行。

发现、中继和 Web 代理是不同职责。用户可以部署多个引导/中继；任意具备相应授权和网络条件的节点可以承担引导，不要求所有节点都承担中继。

不默认运行 RustDesk hbbs/hbbr、RustDesk Web Client 或新的独立远程桌面协调服务。以后接外部 RustDesk 也只作为自带认证与服务依赖的适配器；已有组网和本方案不会自动赋予它兼容协议。

## 14. 故障行为

| 情况 | 应有行为 |
| --- | --- |
| Workspace 离线，节点存在可用直连或其他中继 | 本机客户端/Agent 可继续新建能力调用；目标在本地授权 |
| Workspace 离线，它也是唯一必需中继 | 保留本机任务和 Shell，说明无可用路径；不能保证远端仍可达 |
| 唯一 Workspace Web 入口离线 | 该网页入口不可用，Tauri/CLI/MCP 路径不受其中心网关限制 |
| 多个 Web 入口中的一个离线 | 切换另一个可信入口，重新认证并查询/附着目标会话；不重新执行原请求 |
| 节点目录处于网络分区 | 标记过期/未知，分区恢复后同步收敛；调用依据目标的实时授权 |
| EasyTier 故障，Tailscale 可达 | 新连接走 Tailscale；重新附着终端/桌面，副作用请求不重放 |
| Tailscale 协调服务离线 | 按官方缓存密钥有效性继续已有成员通信，不能保证新增成员和续期 |
| 两个网络都不可达 | 本机保持任务/会话状态，限制缓冲，恢复后查询/附着 |
| 目标节点撤销权限 | 拒绝后续操作并关闭对应流，暂停或取消行为按目标策略执行 |
| 网络分区期间撤销未送达其他目标 | 明确显示未送达；不能保证全网即时撤销 |
| 客户端进程或 OS 重启 | 重新接入网络；不能恢复已死亡 Shell 和非持久进程 |
| VNC 后端无权限、无显示或不兼容 | 命令能力仍可用；桌面显示具体不可用状态或可用备选 |

## 15. Rust 模块与应用组织

保留两个发布方向：Workspace 服务端和独立节点客户端。CLI、Tauri 与 Docker 部署复用同一节点核心和身份模型；服务端默认增加 Web/引导/中继角色，客户端按需启用。两种应用仍分别发布，不让节点依赖整套服务器环境。

浏览器与 Tauri 抽取共享 React 控制台，提供 IPC 和 HTTP/WSS 两个适配器。核心 API 的目标参数、权限错误和会话模型保持相同；现有桌面端的小型配置页面需要迁移到这套共享界面，当前还未统一。

拟议逐步提取：

| 模块 | 职责 |
| --- | --- |
| cranibox-protocol | 版本协商、NodeID、签名能力目录和能力消息 |
| cranibox-node-core | 本地策略、任务、PTY、注册服务和会话租约 |
| cranibox-network | 多路径选择、EasyTier/Tailscale 适配和受管进程 |
| cranibox-desktop | VNC/Selkies 提供者、状态与桌面附件生命周期 |
| workspace-web / workspace-runtime | 浏览器入口、可选引导与旧版兼容 |
| workspace-node / node-desktop | 独立 CLI/MCP 与 Tauri GUI 包装 |

这些是逻辑边界，先按当前 crate 合适位置实现，避免为命名立即拆大量空 crate。现有 workspace-pty 继续提供原生 PTY。第三方组网或桌面服务采用独立受管组件，不为追求一个可执行文件提前重写成熟协议。

资源验收分别记录 Rust 核心、EasyTier、可选 tailscaled、WebView 和桌面后端的空闲 CPU/内存，以及桌面活跃编码的 CPU/带宽。默认只启动已启用提供者，窗口隐藏、远程桌面关闭时减少不必要活动；不预报未经测量的总内存数值。

分发清单记录每个第三方版本、来源、校验和、许可和对应源码获取方式。EasyTier 为 LGPL-3.0，noVNC 主要为 MPL-2.0，LibVNCServer 为 GPL-2.0-or-later，UltraVNC 当前主分支标注 GPL-3.0-or-later [R1][R5][R7][R8]；实际发布按选定版本逐项确认，不把“开源”当作无需处理分发条件。

## 16. 实施顺序与验收

以下按能力分解；实际交付采用[多设备工作空间的纵向流程](distributed-agent-workspace-design.md#8-按日常可用的纵向流程交付)。共享项目视图可以先复用旧网关，随后完成对等路径；项目、消息和 Agent 接续的优先级高于新增桌面后端。

### 阶段 A：组网与身份

先固定 EasyTier 版本，验证 Windows/macOS/Linux 双向用户态能力连接、NAT 穿透、中继与断网恢复；确认无 TUN 支持边界。实现稳定 NodeID、Docker 持久化身份、引导、多个候选成员、签名目录同步、本地授权和 v1 兼容标识。

验收：关闭原 Workspace 后，两个节点可新建命令请求，不只是保持旧连接；使用其他已授权成员邀请新节点；无可用直连或中继时正确报不可达；底层网络成员不能绕过目标应用授权。

另外验证：Docker 重建保持身份，新副本不共用身份；网络分区恢复后目录收敛，旧记录不能覆盖新授权或复活删除项；任一节点都不会因部署在 Docker 内而自动获得其他设备权限。

### 阶段 B：任务、终端、端口和并行网络

将本机 MCP/CLI 路由到节点核心；实现任务去重与查询、PTY 附着、注册端口。接入官方 Tailscale 登录与状态，支持两个网络并行和新连接切换。抽取共享 React 控制台与 IPC/HTTP 适配器，实现任意 Web 入口和统一目标切换。

验收：切换网络不重复执行命令；Shell 在连接断开后仍存在；新路径使用同一 NodeID 和策略；撤销后活跃连接被关闭；端口映射不能访问未注册地址。测试容器 rootless 与真实 OS 环境，不仅在 IPC 模拟中验证。

另外验证：以相同授权主体分别打开两个 Tauri 和 Docker Web，同步完成后设备/能力清单一致；不同授权主体不会看到额外资源。关闭当前 Web 网关后，可从另一个入口找回目标任务；不依赖选主，目标执行记录不复制成第二次运行。

### 阶段 C：项目、跨设备 Agent 与迁移

实现稳定 ProjectID、各节点工作副本、逻辑 AgentSession 与实际 Execution 的区分，建立目标持有的 Agent supervisor、持久消息和 Task/Dispatch 契约。共享 React 界面可从任意入口打开同一项目与会话。先交付跨节点委托、提问与结果，再交付含未提交修改的项目复制、源配合暂停后的会话接续。

验收：换入口不重建执行；断网补投不重复启动 worker；过期 Dispatch 不能完成新尝试；迁移校验代码与上下文，交接不明确时保持暂停，不能因超时双跑。首期不自动接管失联会话，不将 CLI 进程内存或跨 harness 内部状态称为可迁移。详细状态和失败行为以多设备工作空间设计为准。

### 阶段 D：内置 VNC 与浏览器桌面

封装 React/noVNC 和 Rust WSS 转接，优先验证 Windows 用户会话后端、macOS 系统 VNC、Linux X11，以及当前 Selkies 入口。完成随包组件、设置、权限说明、后端检测和桌面会话管理。

验收：三平台实际桌面、锁屏/切换、中文输入、触屏、剪贴板、分辨率、多显示器、掉线重连；窗口关闭仍保持节点服务；关闭 Web 查看器不关闭应用。只读授权必须通过恶意客户端发送输入也无效的测试，否则不对外宣称支持安全只读。

### 阶段 E：远程 Browser Use / Computer Use 能力

接入 Computer Use 与 Browser Use 提供者，统一能力目录、目标授权、输入租约与紧急停止。复用已有 Selkies bridge；新平台驱动在实机验证后才启用。

验收：Agent 操作的是用户看到的同一桌面/浏览器；未授权来源不能访问截图、输入或浏览器配置；人工接管后 Agent 不能继续输入；紧急停止在重连/驱动重启后仍有效。

### 发布前必须解决的验证项

- 固定 EasyTier 发布版的用户态双向接入、独立成员凭据、WSS 反向代理路径；开发分支参考不能代替发布验收。
- VNC 后端在当前 macOS 版本上的 noVNC 认证兼容、只读模式与服务访问限制。
- Windows 后端的用户会话/系统服务边界及安装包分发；Linux 不同 Wayland compositor 的真实能力。
- Tauri 查看器的回环桥授权、Origin 检查和短期凭据清理。
- 按真实空闲/活跃桌面场景测量资源，确定默认启用范围。
