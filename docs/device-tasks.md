# 跨设备协作任务

2026-10-17：Web 与 Tauri 共用“协作任务”页面。独立节点在本机保存委托、领取记录、进度、提问、回复与结果；接收方可检查并确认启动后台 Agent，或由 Agent 使用 device_tasks MCP 工具主动领取。已有直连、EasyTier 或 Tailscale 路径都可以承载任务，Workspace 中继不参与此流程。

默认需要明确领取任务；[本机后台执行](agent-executions.md)提供节点托管的程序启动和进程结果。接收设备可另外明确配置下述自动接单策略，未配置时接收任务不会启动模型或创建 worker。任务描述始终作为外部数据通过标准输入交给已选 Agent，不作为 Shell 命令执行，也不向活动终端输入。目标为 NodeID，可额外指定主动登记的 session UUID；登记与续期见[Agent 会话](agent-sessions.md)。执行方领取时提供自己的稳定 session UUID；它是任务归属与路由标识，不是认证凭据，也不是自动发现的 harness 进程。

## 先建立连接与授权

按照[节点直连](direct-node-peers.md)保存 NODE_A 到 NODE_B 的路径。在 NODE_B 授予 NODE_A 消息权限：

~~~sh
cranibox peer grant --node NODE_A --output-token ./node-a.token --messages
cranibox peer serve
~~~

界面的“设备消息与协作任务”开关默认关闭。它允许查询公开 Agent 登记、消息与任务请求投递，以及查询自己请求的回执、进度与结果；不授予命令、终端、项目或桌面访问权限。目标 Agent 保持原有工具权限，并把任务描述视为外部输入。已有授权需撤销后重新签发，更新发送方保存的凭据。

任务结果通过发送方重复查询同一投递返回，不要求 NODE_B 配置反向连接。普通消息的线程回复仍要求反向连接。

## 页面操作

1. 在“协作任务”选择执行设备，再选择有效的执行 Agent 或设备级委托，填写标题、目标与完成条件，点击“保存并委托”。本机先持久保存，再由后台投递。
2. 在目标设备查看“发给本机”。设备级任务可点击“用 Agent 处理”，选择 Codex / Claude Code、权限和工作目录，检查完整指令后确认领取并启动。也可复制领取说明交给已有 MCP Agent；指定会话的任务保留原会话归属，不能替换为新进程。
3. 执行方报告进度，需要确认时提交问题。发送方在“我的委托”保存回复，页面区分本机排队与目标已确认。执行方读取确认答案后自行继续，再明确报告最终结果；投递成功或会话空闲不代表完成。
4. “请求停止”持久保存取消意图。未被领取的任务在目标确认后直接取消；已领取的工作等待执行方在安全边界停止并报告。自动接单策略启动的进程由接收节点停止并确认终止；手动领取的进程仍需执行方明确停止。取消不表示此前修改已经回滚。
5. “同步原尝试”只查询或重投原 DispatchID。只有明确失败或取消后，才可经确认创建新尝试；旧尝试历史保留。
6. 只有终态可归档。归档保留去重与最终回执，不撤回已交付数据。

关闭页面后，由 Web、本机节点服务或 MCP 进程继续同步。关闭所有这些进程会暂停同步，记录仍保留。重启恢复相同任务和尝试，不自动再启动一次执行。不同设备使用相同页面不表示它们的完整任务库已同步。

## 将多项委托放入同一次协作

2026-10-18：共享页面增加“多设备协作”。先填写固定名称、共同目标与完成条件，选择 1–16 个已保存连接的参与设备；ProjectID 可选。创建后通过“添加委托”填写具体任务，执行设备只可选择本次协作成员，也可定向到成员上有效登记的 Agent。创建协作本身不会创建任务或启动 Agent。

每次协作使用 RunID，完整身份为协调节点 NodeID + RunID。协作保存在发起节点的任务账本中，接收任务携带不可变的名称、目标、协调节点和可选 ProjectID；接收方 MCP 及“用 Agent 处理”的检查指令都能读取这些上下文。接收上下文不会在目标创建设备管理权，也不授予命令、终端、文件、桌面或执行权限。每项任务仍需明确领取及报告。

参与设备与原连接/凭据绑定，创建后不能修改。更换地址或授权后不能将原协作继续派发到新绑定；已有任务按原绑定停止投递，不会静默改投。可建立新的协作继续后续工作。界面统计成功、失败、取消、待报告和待回复任务，可按协作筛选；不同协调节点碰巧使用相同 RunID 时仍分开显示。协作内任务以整次协作为单位归档，保持汇总与历史一致。

“请求停止全部”经确认后，一次持久保存协作停止状态及全部未完成任务的取消请求，同时拒绝新任务和新尝试。目标离线或执行方尚未确认时仍显示等待，不推断程序已停止。所有任务的当前尝试均收到最终回执后，操作者才可填写核对后的总结并结束协作，再确认归档。停止、结束与归档携带当前 revision；过期修订拒绝操作，响应不确定时复用原 ID、内容及 revision 重试。

CLI 与 device_tasks MCP 使用相同命令：

~~~json
{"operation":"collaboration","command":{"operation":"create","id":"44444444-4444-4444-8444-444444444444","name":"跨设备构建复核","goal":"对同一项目版本分别检查构建并报告证据。","members":["NODE_B","NODE_C"]}}
{"operation":"create","id":"11111111-1111-4111-8111-111111111111","dispatch":"22222222-2222-4222-8222-222222222222","node":"NODE_B","run_id":"44444444-4444-4444-8444-444444444444","title":"检查构建","description":"核对当前日志并明确报告结果。"}
{"operation":"collaboration","command":{"operation":"stop","id":"44444444-4444-4444-8444-444444444444","revision":1}}
{"operation":"collaboration","command":{"operation":"close","id":"44444444-4444-4444-8444-444444444444","revision":2,"result":"已逐项核对全部最终回执。"}}
{"operation":"collaboration","command":{"operation":"archive","id":"44444444-4444-4444-8444-444444444444","revision":3}}
~~~

这些示例为分步调用；只有实际满足前置条件时才执行下一步。列表返回 collaborations、collaboration_used 和 collaboration_capacity。最多保留 32 次协作，名称最多 240 UTF-8 字节、共同目标 4096 字节、总结 8192 字节。归档保留去重记录与任务回执；整次协作及关联任务均归档且保存期限到期后，一起回收。创建响应不确定时复用原 RunID、完整内容和成员列表，不另建一次协作。

协调节点离线时已领取的工作可继续，新的派发与协调操作等待原节点恢复。下述基础任务依赖仅控制派发；接收设备可自行启用自动接单，不复制全网任务库或选举协调者。普通不带 run_id 的任务保持兼容；协作任务增加 collaboration 字段，发送方和接收方均须升级，旧接收方拒绝未知字段时不会剥掉上下文后降级重投。含协作记录或任务依赖的发送方账本需要新版程序读取；回退程序前应恢复与旧版本对应的账本备份。

### 按前置任务结果派发

同一次协作中，创建委托可选择最多 8 项已存在的前置任务；也可通过 create 的 depends_on 数组传入 TaskID。只有全部前置任务的当前尝试明确报告 succeeded，协调节点才会持久记录放行并向目标派发。界面显示“等待前置任务”及各项最新回执，协作汇总单独统计等待数量。任务可跨参与设备依赖；前置任务列表创建后不可修改。

~~~json
{"operation":"create","id":"55555555-5555-4555-8555-555555555555","dispatch":"66666666-6666-4666-8666-666666666666","node":"NODE_C","run_id":"44444444-4444-4444-8444-444444444444","depends_on":["11111111-1111-4111-8111-111111111111"],"title":"复核构建产物","description":"先核对项目版本与产物位置，再报告复核证据。"}
~~~

前置任务失败、取消、失联或状态未知均不会放行；操作者可明确重试前置任务，或取消等待中的委托。“重新检查前置任务”不绕过成功条件。等待记录、放行与取消意图保存在发送方，重启后继续；接收方仍只看到正常委托，不需要依赖协议扩展，是否自动领取由接收设备策略决定。依赖只约束派发顺序，不自动复制项目、文件或产物，任务说明应写清要核对的版本及路径。

从未放行的委托可在发送方直接取消，并记录“派发前已在本机取消”；即使目标离线或原授权已变化，也不会留下需要目标确认的执行。协作“请求停止全部”同时取消这些未发送委托。已经放行的委托继续遵守原远端取消流程，不能根据同步次数或网络错误推断它尚未到达目标。

| 状态 | 含义 |
| --- | --- |
| queued | 委托已保存在发送方；等待依赖时明确尚未派发，其他情况目标是否已保存尚不确定 |
| available | 目标已持久保存，等待 Agent 领取 |
| running | 一个明确的会话已领取；不代表进程当前仍存活 |
| cancel_requested | 目标已记录停止请求，执行方尚未确认结束 |
| succeeded | 已领取的会话明确报告成功 |
| failed | 已领取的会话报告失败，或目标明确拒绝未领取任务 |
| cancelled | 目标确认取消、已领取会话明确确认停止，或发送方确认从未放行并在本机取消 |

网络异常显示最后已知状态、同步时间和错误。超时不能证明工作停止，也不允许据此创建新尝试。请求取消后，工作若已经完成，执行方仍可报告实际成功或失败。

## CLI 与 Agent MCP

本机 CLI 使用同一份类型化命令，无网关设置也能运行：

~~~sh
cranibox peer tasks
cranibox peer tasks --command '{"operation":"list"}'
~~~

创建时生成并保留两个不同用途的非零 UUID：TaskID 标识工作，DispatchID 标识一次尝试。创建响应不确定时，必须用相同 ID、内容与目标重试。

~~~json
{"operation":"create","id":"11111111-1111-4111-8111-111111111111","dispatch":"22222222-2222-4222-8222-222222222222","node":"NODE_B","title":"检查构建","description":"读取构建日志，报告失败原因与证据；不要更改发布配置。"}
~~~

Agent MCP 沿用现有独立入口；不需要 Workspace 地址：

~~~json
{
  "mcpServers": {
    "cranibox-messages": {
      "command": "cranibox",
      "args": ["peer", "messages", "mcp"]
    }
  }
}
~~~

此入口提供 device_messages、device_tasks 和 device_agent_sessions。以下 JSON 是 device_tasks 的参数，也可以传给 peer tasks --command。Agent 先读取目标当前 DispatchID，再生成并保留自己的 session UUID：

~~~json
{"operation":"list"}
{"operation":"claim","id":"11111111-1111-4111-8111-111111111111","dispatch":"22222222-2222-4222-8222-222222222222","session":"33333333-3333-4333-8333-333333333333"}
{"operation":"progress","id":"11111111-1111-4111-8111-111111111111","dispatch":"22222222-2222-4222-8222-222222222222","session":"33333333-3333-4333-8333-333333333333","text":"已检查两份日志，正在复核退出码。"}
{"operation":"finish","id":"11111111-1111-4111-8111-111111111111","dispatch":"22222222-2222-4222-8222-222222222222","session":"33333333-3333-4333-8333-333333333333","outcome":"succeeded","result":"构建成功，测试通过；证据位于 build.log。"}
~~~

create 可选 target_session；同一任务的目标会话不可更改。定向任务首次 claim 要求 UUID 一致且有有效的本机登记；旧设备级任务不需要登记。登记过期或结束不会终止已经领取的工作，原会话仍需报告结果。session UUID 不隔离受信任本机 CLI/MCP 的权限。

finish 的 outcome 为 succeeded、failed 或 cancelled，必须提供结果说明。同一会话重复领取返回原记录；其他会话无法领取同一次尝试。重复的最终报告必须完全相同，最终结果不能改写；新尝试开始后，旧 DispatchID 不能更新当前尝试。

其他命令：decline 需要 reason，只能拒绝未领取任务；cancel、sync、archive 需要 id 和当前 dispatch；retry 还需新的 new_dispatch，只有收到明确失败或取消结果后才允许。重试响应不确定时复用原 dispatch 与 new_dispatch 的组合，不能每次生成一个新值。

自定义配置使用 --config /path/to/settings.json，放在 peer 前。普通 CLI 仅持久入队，需要节点服务、Web、Tauri 或 MCP 至少一个进程存活才能后台投递。MCP 可负责出站同步；接收远端投递还需要监听服务。

## 任务卡中的 Agent 执行

检查和启动属于接收设备本机操作者操作，Web 与 Tauri 共用同一实现。默认只读，CLI 需预先安装、登录；检查只确认可执行文件、目录与启动内容，不验证模型账户。确认后可能产生模型费用。Codex 使用对应沙箱，Claude Code 使用工具限制；具体边界见[后台执行](agent-executions.md)。任务文本通过标准输入传入，不拼成 Shell 命令，不写入进程参数。

每个 TaskID / DispatchID 持久绑定唯一的运行 ID、执行会话、检查摘要与完整启动内容。第一次确认先保存领取与绑定，再入队；如果容量不足或保存后进程尚未入队，卡片显示保留记录，明确使用原检查内容重试。重复确认、关闭页面或网络恢复不会再创建一个 Agent。节点重启把已有未完成进程记录标成 interrupted，不自动重跑；尚未入队的保留记录也只在再次明确提交后启动。

卡片可分页查看中文输出、暂停观察、找回原运行及明确停止该任务进程。关闭浏览器或切换客户端页面不终止节点持有的进程；执行节点退出的恢复边界仍遵守后台执行文档。普通“请求停止”只是协作取消意图；“停止任务进程”需确认并终止本任务的受管进程树，两者都不会替代结果报告。

进程进入终态后，操作者必须选择核对后的任务结果并填写证据。退出码 0 不自动完成任务，非零退出也不替代任务结果判断。后台进程仍活动时，普通 finish 和任务运行的 finish 都拒绝最终报告，避免提前重试造成并行执行。明确报告仍通过原投递同步给发起方，无需反向连接。

撤销或轮换消息授权会阻止新的领取和保留记录重新入队，但不会杀掉本机操作者已确认的运行；本机仍可查看、停止和报告它。消息权限不包含启动权限，device_tasks MCP 明确拒绝 run 操作，远端任务路径也不接收启动命令。已有 Agent 如需启动其他运行，须单独配置执行 MCP 及相应授权。

本机 CLI / 已登录 Web / Tauri 可调用以下额外命令；device_tasks MCP 不提供它们。所有命令携带当前 id 和 dispatch，command.operation 分别为 prepare、start、get、stop、finish。prepare 需要 options，start 使用检查返回的同一 options 和 digest；get 可指定 stdout_offset、stderr_offset；finish 需要 outcome 和 result。示例：

~~~json
{"operation":"run","id":"11111111-1111-4111-8111-111111111111","dispatch":"22222222-2222-4222-8222-222222222222","command":{"operation":"prepare","options":{"adapter":"codex","access":"read_only","cwd":"/home/user/project"}}}
~~~

启动绑定仅保存在接收设备的任务账本，回执线协议不增加运行详情。升级使用此功能的接收设备；旧二进制可能拒绝包含绑定字段的本地账本，回退前保留数据并核对兼容性。任务副本不是完整执行日志或长期审计库。

## 本机自动接单

2026-10-18：Web 与 Tauri 的协作任务页共用“本机自动接单”，默认关闭。浏览器中的本机是托管 Workspace 的节点；Tauri 中是客户端所在设备。接收设备选择已有消息授权的可信发送节点、固定绝对工作目录、Codex / Claude Code、文件权限、1–4 个并发进程及结果回报方式，检查配置后再明确确认保存。检查不启动程序、不验证模型登录。启用会处理已经等待的普通任务，也可能产生模型费用。指定给既有 session 的任务不由自动接单接管；发送方不能在任务中指定接收端启动配置。

节点服务每两秒检查持久队列，关闭页面后继续工作。进程归属仍使用原 TaskID / DispatchID 及唯一执行和会话绑定；已有执行记录无论成功、失败或中断都不会自动重跑。若领取已保存、执行队列尚未写入，恢复时只会重用原绑定；历史已满时可在后台执行页面归档旧记录，并等待保留期回收。暂停仅阻止新启动，已经运行的进程继续；每项任务仍可查看输出并明确停止。发送方取消会停止自动进程，在确认进程终止后回报 cancelled，明确说明不是回滚。节点重启造成的 interrupted 需要人工核对，不能自动推断停止结果或采用候选结果。

默认的“人工核对后回报”保留手动提交。可另选“自动回报 Agent 提案”：Agent 必须通过本任务 cranibox_task/propose 明确保存候选结果，进程正常结束且没有未答问题后才允许回报。成功提案要求退出码 0；非零退出只允许回报 failed 提案。没有提案、运行中、被取消或重启中断都不自动完成。回报是 Agent 声明，不能替代真实结果验证；已有运行保留其启动时的回报策略，不随新策略改变。

自动策略同时绑定发送方的当前消息授权摘要；撤销或轮换该授权会阻止新接单并停止关联自动进程，重新签发也不会恢复旧策略，需要接收设备重新检查和确认。手动由本机操作者确认的运行保持原有撤权行为。策略以私有文件 task-worker.json 保存在 peers.json 同目录，Unix 为 0600，包含授权摘要而不是原始 Token。旧二进制不保证能读取自动执行的绑定及进程记录；回退时保留并使用对应版本备份。

仅本机 CLI、已登录 Web 与 Tauri 可配置；device_tasks MCP 和远端任务投递路径不能配置。节点 CLI 使用 peer tasks --command，服务端使用 cranibox peer tasks --command；命令外层为：

```json
{"operation":"automatic","command":{"operation":"get"}}
```

prepare 需要当前 revision 和 options；options 包含 enabled、senders、agent（adapter、access、cwd、communication:true）、parallel 和 report（human_review 或 agent_proposal）。保存时使用 prepare 返回的同一 revision、规范化 options 和 digest；配置或授权变更会拒绝过期确认。响应丢失时重试原 save，不会新增策略代次。pause 携带当前 revision，重复请求保持幂等。没有消息授权时须先配置设备授权；不自动开放权限、安装 CLI 或发送凭据。

其他窗口更改配置后，表单保留当前修改，但不自动合并或覆盖。刷新接单状态后，可点击“保留修改并重新检查”，按当前版本重新核对并再次勾选确认。保存响应未知时仍可重试原检查结果；若服务端明确拒绝过期版本，则返回修改后重新检查。

test_automatic_task_worker.py 的 14 项测试使用真实双节点 HTTP、Rust 进程管理及隔离模型 CLI 替身，验证默认关闭、配置检查、重复保存、队列与并发、暂停、观察端关闭、授权轮换、取消、提案回报及重启去重；包含历史满额时取消尚未入队的运行、恢复同一绑定、策略变更后不自动接管旧预留，以及未答问题阻止自动报告。没有调用真实模型。

## 经确认启动的 Agent 与任务沟通

任务卡提供默认关闭的“启用任务沟通工具”。勾选后，检查页面会展示加入本次启动的 MCP 配置和指令；确认时的摘要包含这一选择和完整启动内容。Codex 与 Claude Code 启动专属 stdio MCP 服务，只提供 cranibox_task。没有改写账户的全局 MCP 配置，也不增加消息 MCP 的程序启动权限。

| operation | 用途 | 参数 |
| --- | --- | --- |
| get | 当前任务正文、派发、会话、进度、已确认问答和取消状态 | 无 |
| wait | 等待回执修订变化，或在指定时间返回当前内容 | after_revision、timeout_secs（1–30 秒） |
| progress | 保存本任务的进度 | text（4096 UTF-8 字节） |
| ask | 提交一个问题；使用稳定 ID 和相同原文重试 | question（非零 UUID）、text（4096 字节） |
| propose | 持久保存一个候选结果，等待操作者核对 | outcome（succeeded / failed / cancelled）、result（8192 字节） |

工具不接受其他 TaskID、DispatchID、NodeID 或 session 参数。启动入口固定本次绑定，每次调用重新检查原消息授权、当前派发、唯一运行身份和进程状态；撤权或轮换凭据、归档、进程停止及更换尝试后不能继续使用。wait 每半秒复核一次，期间不持有凭据锁；收到回复或取消请求可提前返回。问题与回复仍经过原有持久投递协议，不需要反向连接。运行节点和发送方同步进程须继续运行；关闭观察网页不会停止它们。

候选结果一经保存不能由工具改写；相同内容重试返回原候选。工具本身不会完成任务。默认在进程退出后，由页面点击“填入报告供我核对”，已有草稿会先确认替换，再允许修改结果和证据、明确提交。刷新页面能找回候选，但不会自动采用。明确启用上述自动回报策略的运行按该策略处理；get 中 review_required 表明本运行是否需要人工核对。候选只保存在接收方绑定中，发送方收到的是最终报告；不增加任务回执线协议。

MCP 的范围约束用于避免误调用，继承本机账户信任边界；任务 UUID 与文件路径不是隔离凭据。它不改变 Codex 沙箱或 Claude 文件工具权限，不保证模型一定等待回复或遵循取消。工具不能启动其他程序、向活动终端注入输入、配置自动接单或迁移运行会话。关闭此选项保留原有手动适配器行为；自动接单必须启用本任务沟通，启动后不能切换已绑定配置。

内部入口由当前 Cranibox、独立节点、运行库、独立 Web 或原生客户端程序承载，不需要另装常驻 MCP 守护进程；AppImage 使用其启动文件。仅包含绝对 peers.json 路径与本次任务/派发 ID，不在命令参数中加入连接 Token。完整配置属于检查结果，不建议手工复用到其他任务。

适配参数依据核对时的官方文档：[Codex MCP](https://developers.openai.com/codex/mcp/) 与 [Claude Code CLI](https://code.claude.com/docs/en/cli-reference)。test_task_worker_mcp.py 用隔离 CLI 替身读取实际注入配置，启动真实 Rust stdio MCP，并经过真实双节点 HTTP 完成问答和候选结果；覆盖所有 Rust 入口、等待超时、取消、撤权、凭据轮换和旧派发拒绝。测试不调用模型，不能替代实际安装版本、账户登录及模型工具调用验收。

## 执行中的提问与回复

已领取的执行方使用 ask 提出一个问题，session 必须匹配当前执行归属；question 是执行方生成并保留的非零 UUID。同一 DispatchID、QuestionID 与原文可以重复提交，不能替换问题内容。每次尝试最多 8 个问题，同时只能有一个问题等待回复；问题与答案各最多 4096 UTF-8 字节。新增问题还要求发送方授权有效。

~~~json
{"operation":"ask","id":"11111111-1111-4111-8111-111111111111","dispatch":"22222222-2222-4222-8222-222222222222","session":"33333333-3333-4333-8333-333333333333","question":"77777777-7777-4777-8777-777777777777","text":"需要检查哪个发布分支？"}
~~~

发送方同步原尝试，看到问题后可以在 Web/Tauri 中回复，也可以使用本机 CLI/MCP 的 answer：

~~~json
{"operation":"answer","id":"11111111-1111-4111-8111-111111111111","dispatch":"22222222-2222-4222-8222-222222222222","question":"77777777-7777-4777-8777-777777777777","text":"检查 release 分支，完成后先报告测试证据。"}
~~~

回复先保存到发送方的 pending_answer。网络恢复后，原任务投递会携带回复；目标持久保存并在 questions[].answer 中返回相同内容后，才算交付确认。不需要目标到发送方的反向路径。关闭页面不丢失已排队回复，重新启动服务继续投递；所有同步进程关闭时暂时不投递。仅填写但尚未保存的表单草稿不落盘。

已排队和已确认的答案不可修改；响应不确定时使用相同的 TaskID、DispatchID、QuestionID 和原文重试。目标尚未确认时不能把 pending_answer 当作已收到；若目标回执中的答案与排队原文不同，会保留本机记录并阻止继续同步，供用户核查。旧尝试的回复始终只关联原 DispatchID，不能进入新尝试。页面观察到新尝试后会清除旧尝试尚未保存的回复草稿。取消请求会清除本机尚未投递的回复；已在网络中的消息可能先于取消到达。目标已记录停止或终态后，迟到的回复不会改变执行状态或最终回执。

未使用问答的记录省略扩展字段，现有任务仍可读取。使用问答前需升级收发双方；旧版本可能拒绝带新字段的回执或投递。此时保留原尝试并显示同步错误，不自动改投或重跑。

“等待回复”是从问题记录派生的页面提示，底层任务仍为 running。协议不暂停进程，也不监控执行方是否遵守等待：Agent 应自行在安全边界等待，定期读取 questions[].answer 与 cancel_requested。如果工作已结束，执行方仍可明确报告结果。答案是外部输入，不能扩大既有工具权限；它不是危险操作的系统授权。Agent 会话登记中的 waiting 状态需由 Agent 自行续报。

## 持久化与边界

- 存储位于 peers.json 同目录的 device-tasks.json。Unix 使用 0600、文件锁和原子替换；损坏或归属错误时保留并报错，不重置成空库。任务正文与报告未做静态加密，不保存明文目标 Token。
- 每台设备最多 128 项收发任务，包含尚未清理的归档；文件上限 16 MiB，每项最多 8 次尝试。标题最多 240 UTF-8 字节，描述和结果各 8192 字节，进度 4096 字节。
- 新尝试须在任务创建后 7 天内领取。期限到期不终止已领取工作，也不自动产生失败。仍可记录结果或确认取消。过期的未完成任务需明确结束后归档。
- 任务与完整内容、认证发送方、目标、投递凭据绑定。同一 TaskID 改变内容会拒绝；令牌轮换后不能用新凭据读取旧回执或领取旧任务。已领取的本地执行方仍可记录真实结果。
- 发送方记录绑定原路径与凭据。变更后停止旧任务自动投递；重新添加同一地址也不会解除旧记录的绑定。需到原目标核实实际状态；当前没有重新绑定旧任务的界面，不能将不确定的旧执行直接搬到新目标。
- 目标每次检查授权。原消息权限只允许投递任务或查询自己在相同凭据下发出的回执，不允许读取完整任务库。新增、独立的 activity 只读授权可汇总当前报告，见[跨设备协作记录](federated-activity.md)。两者都不能远程调用 claim、progress、ask 或 finish，这些操作属于本机受信任 CLI/MCP。
- 归档终态在领取期限之后，于下次需要容量的保存时清理。期限内保留去重记录；仍占容量。它不是无限期审计日志。

| 方法 | 目标路径 | 含义 |
| --- | --- | --- |
| POST | /api/v1/mesh/nodes/{NodeID}/tasks | 幂等投递原任务/尝试，可携带取消请求或问题回复；返回当前回执 |
| GET | /api/v1/mesh/nodes/{NodeID}/tasks/{TaskID}/{DispatchID} | 仅查询当前认证发送方和原凭据绑定的回执 |

Web 同源 POST /api/peers 使用 {"operation":"tasks","command":{...}}，沿用登录、CSRF 与同源检查；Tauri 通过本机 IPC 调用同一个 Rust 实现。直连接口继续拒绝浏览器 Origin、校验目标与请求大小，并禁止重定向。

## 验证与后续

Rust 测试覆盖持久化、并发领取、幂等、明确重试、取消、撤权、旧报告、归档去重与损坏数据。test_device_tasks.py 用真实 HTTP、CLI 和 MCP 验证独立双节点、关闭中继、离线重启、无需反向路径的回复和结果回传、MCP 问题重试、凭据与身份检查。浏览器和 Tauri 模拟 IPC 测试覆盖共用页面、响应不确定时保留 ID、回复提交失败保留原文、排队和交付状态、移动布局与纯文本展示。

主动会话登记、UUID 定向任务、持久问答、明确确认的任务执行绑定、任务专用 MCP 沟通、可选自动接单及 Codex / Claude Code 非交互适配已提供。test_task_runs.py 使用隔离 CLI 替身验证真实双节点领取、一次启动、输出分页、观察端重启、队列失败后的明确恢复、取消与新尝试、撤权和 MCP 权限边界，没有调用模型。test_collaboration_runs.py 与 test_task_dependencies.py 覆盖协作汇总、统一停止、依赖成功后派发、失败等待、离线取消及重启恢复。尚未提供进程自动发现、项目范围授权、复杂自动编排、交互输入与恢复或运行会话迁移。这些继续按[多设备项目与 Agent 工作空间设计](distributed-agent-workspace-design.md)实现。
