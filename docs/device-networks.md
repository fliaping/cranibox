# 设备自动组网

Web 和 Tauri 在“设备网络”共用 EasyTier、Tailscale 管理界面。网络属于运行 Rust 节点的设备：Web 管理的是 Workspace 主机（包括 Docker 容器），Tauri 管理的是安装客户端的电脑。浏览器所在电脑不会因为打开网页自动加入网络。

EasyTier 使用节点托管的独立进程，可以在没有 Workspace 网关的两台设备之间发现节点并调用已授权能力。Tailscale 复用系统现有服务，提供状态、设备列表、官方登录入口，以及指定端口的持续发现、按设备查找和接入 Cranibox 节点。两者可同时存在，同一设备可以保存多条路径；新连接按保存顺序选择可用路径，已有 TCP/WebSocket 连接不做无缝迁移。

## 两台设备使用 EasyTier

1. 在两台设备的“设备网络 → EasyTier”查看安装计划，核对版本、平台、下载地址、SHA-256 和安装目录，再点击安装。当前固定使用上游 **2.6.4**，支持 Windows、macOS、Linux 的 x86_64/ARM64；这不是随启动自动下载或跟随 latest 更新。
2. 选择一台可达设备 A，切换到“手动填写地址”，展开高级设置，启用入站连接。默认监听端口为 `11010`，同时使用 TCP 和 UDP。填写网络名称，生成网络 Token，连接。其他成员需要使用相同的名称和 Token。
3. 设备 B 可以使用下述短期邀请加入；也可以切换到“手动填写地址”，填写 A 的实际可达地址，例如 `tcp://192.168.1.20:11010`，填写相同的网络名称和 Token，连接。没有公网入站能力的设备可以通过另一台可达成员接入。此地址是 EasyTier 协议入口，与 Workspace 的 HTTP 地址、`/ws/nodes/*` 不同。
4. 两端发现对方后，在目标设备的“入站授权”为调用方 NodeID 签发所需的命令、终端、项目和/或桌面权限。把这个目标访问 Token 填入调用设备的“连接发现的设备”。反方向访问需要独立授权。
5. 保存后，设备出现在共享直连列表，可检查权限、执行命令、打开浮动终端、访问项目目录，或连接已开启共享且授予桌面权限的 VNC 服务。Agent 复用现有 `peer call --node NODE …` CLI/MCP 入口。

“网络入口”支持每行一个地址，最多 8 个，可以同时填写多台可达成员的 TCP、UDP 或 WebSocket 地址。EasyTier 会尝试这些入口；某个入口离线后，其他可达成员仍可接纳重连设备，无需重新指定主节点。至少保留一台实际可达且开启入站的成员；所有入口都不可达时不能保证重新加入网络。设备地址不是目标访问凭据，也不会自动开启能力授权。

目标访问 Token 与网络 Token 是两个不同凭据。网络 Token 允许加入可信网络，不自动授予设备能力；目标访问 Token 由目标节点验证。安装和连接失败会保留表单输入；成功后清除表单中的秘密，不写入浏览器存储。关闭页面或窗口不会停止节点的网络进程。

### 使用 Workspace 地址与短期邀请

1. 在已连接 EasyTier 的 Workspace 网页中展开“邀请其他设备”，核对入口地址。可以填写多个在线成员；新设备必须能访问至少一个入口。点击“创建 15 分钟邀请”。
2. 向可信设备分享页面给出的 Workspace 地址和邀请 Token。邀请只展示一次，不包含在 URL 中；刷新后不能重新查看 Token，但仍可查看到期时间或撤销。
3. 新设备安装 EasyTier 后，在 Web 或 Tauri 的“使用邀请”中填写地址和 Token，点击“通过邀请加入”。Rust 后端领取网络名称、网络秘密及入口列表，并保存到本节点私有配置；浏览器不跨域读取对方的秘密。
4. 加入网络不会创建任何目标能力授权；仍需上述第 4 步的目标访问授权。

邀请以 `cbi_` 开头，15 分钟内有效，每个邀请只接入一台设备。首次领取时绑定客户端私有恢复凭据；原设备在邀请到期前可以重试，其他领取请求会被拒绝。重试不延长到期时间。页面显示“等待设备领取”或“已领取 · 仅原设备可重试”；领取后隐藏仍在页面中的邀请 Token，恢复窗口内仍可撤销。每个节点最多保留 16 个有效邀请，包含已领取但尚可恢复的邀请。

`network-invitations.json` 保存邀请及恢复凭据的哈希、领取与到期时间、网络绑定和入口地址，不保存邀请明文、恢复凭据明文或网络秘密。正常重启保留未过期记录。撤销会阻止后续领取和恢复，不能收回已经交付的网络秘密；需要移除已有网络成员时应更换网络 Token。断开期间邀请不可用，重新加入网络会清空旧邀请，避免重新激活。

领取接口是 `POST /api/network/bootstrap`，请求体为 `{"recovery":"64 位十六进制恢复凭据"}`，上限 128 字节，邀请凭据放在 `Authorization: Bearer cbi_…`，不使用浏览器会话或 CSRF。仍接受旧客户端的空 JSON 对象，但该模式领取后立即消费邀请，不支持恢复。旧服务端会拒绝新的恢复字段；客户端提示升级邀请方 Workspace，不自动退回无法恢复的领取方式。其余网络管理接口仍保留原会话、CSRF、Host 和同源限制；此接口也不放宽 Host、Origin 或缓存限制。HTTPS 反向代理应让此路径使用邀请鉴权，其余管理页面继续使用原有访问控制。

客户端只接受专用 HTTPS origin，拒绝凭据、路径、查询、片段、HTTP 重定向和超过 32 KiB 的响应。仅字面回环 IP 允许 HTTP，供本机测试使用。客户端本地尚未安装 EasyTier、已有网络、配置损坏、端口或地址无效时，不发起领取。

客户端先在 `networks.json` 旁以私有权限保存 `network-enrollment.json`，再发送领取请求。该文件只包含地址与邀请的组合哈希和随机恢复凭据，不包含邀请明文或网络秘密。领取响应丢失或本地网络配置写入失败时，在原设备填写相同 Workspace 地址与邀请重试；客户端重启后仍使用相同凭据。网络配置成功保存后清理恢复文件。每个节点只保留一份待恢复领取；改用另一地址或邀请会替换它，无法再恢复前一次领取。损坏的恢复文件会保留并报告错误，不静默覆盖。恢复凭据不是节点公钥或设备证明，复制它和原邀请也能恢复，应按秘密文件保护。

出现已领取记录后，旧服务端无法读取新增的恢复字段。回退程序时需同时恢复升级前的 `network-invitations.json` 备份；不能只替换程序并假定这些记录向后兼容。

邀请只负责引导网络配置，不把 Workspace HTTPS 端口变成 EasyTier 协议端口。需要按下节发布实际 TCP/UDP 监听；也可以在邀请中填写其他可达成员。初次建网和无 Workspace 网页的节点仍可手动接入；连接完成后不依赖邀请签发节点持续在线。

### Docker 和端口

容器选择充当入站成员时，需额外发布所选端口。例如，`docker-compose.yml` 的 `ports` 可加入：

~~~yaml
- "11010:11010/tcp"
- "11010:11010/udp"
~~~

监听端口变更时同时修改端口映射和防火墙。仅向已有成员主动连接的容器不需要发布这个端口。Cranibox 不会替宿主机自动修改防火墙、UPnP 或 Docker 端口。不要把容器回环地址作为其他设备的接入地址。

## 进程、凭据与恢复

节点只运行自己私有安装目录内的 `easytier-core` 和 `easytier-cli`，不会接管已有系统 EasyTier。下载使用固定官方 HTTPS 地址，校验 SHA-256 后才解压两个程序；失败或不完整的下载不会发布为有效安装。

连接使用用户态 SOCKS/TCP 转发，不创建 TUN、不修改系统路由或 DNS，也不需要为此授予管理员权限或 `NET_ADMIN`。EasyTier 内部仍使用自动分配的地址，界面按稳定 Cranibox NodeID 管理设备。当前只向同网络成员发布节点能力服务的 TCP 端口，不开放任意宿主端口或通用 UDP 转发。入站 EasyTier 监听仅在用户明确启用时创建。上游可能使用自身的穿透服务；用户态模式不等于完全没有外部网络访问。

配置保存在 `peers.json` 旁的 `networks.json`，包含网络秘密和稳定的本机转发端口；程序位于相邻的 `tools/easytier-2.6.4/`。运行时生成私有 `easytier.toml`，秘密不放进命令参数或状态响应。Unix 私有文件权限为 `0600`；Windows 使用当前用户的配置目录。应连同 `peers.json` 及其目标 Token 文件一起备份，不要将秘密配置提交到仓库。

新配置使用 `easytier.peers` 数组保存全部入口，旧 `peer` 单地址配置继续读取。两种字段不能同时填写非空值；重复地址、无效的任一入口或超过 8 个入口会在写入前拒绝，不覆盖原配置。状态响应不含网络 Token。

节点重启后会读取保存的网络配置，恢复网络和已保存连接。异常退出会有限退避重试，连续失败五次后停止尝试；检查环境后可以断开再连接。保存的本机端口若被其他进程占用，状态会报告错误，需要释放端口并重启节点。托管连接带有本机进程持有的锁标记；命令、终端和桌面连接在发送凭据前检查转发是否仍由节点持有，防止正常退出后把旧端口当作仍可用的节点入口。这是本机生命周期检查，不是远端的密码学身份认证。

“断开 EasyTier”禁用自动恢复、终止本节点管理的进程，并删除临时 TOML；保留安装文件、已保存目标凭据和原 NodeID。网络断开只关闭网络通道，不结束其他节点上的 Shell。退出节点进程会结束它自己持有的原生 Shell，重新启动不会恢复原 Shell 进程。

没有图形界面或不连接 Workspace 时，可使用相同配置运行 `cranibox-node --config /path/to/settings.json peer serve`，持续托管已经配置的网络与桌面服务；仅通过 EasyTier 接入的节点不要求额外开启局域网 HTTP 监听。不要同时用同一配置启动 Web、Tauri 或另一个节点进程。

## 与系统 Tailscale 共存

界面读取当前用户可用的系统 `tailscale status --json`，展示登录状态与有限的设备信息。需要登录时启动官方 `tailscale login --accept-dns=false --timeout=5m`，登录链接在浏览器打开；Tauri 使用系统浏览器。本次登录不接收 tailnet 下发的 DNS 配置；系统 Tailscale 仍会按自身行为建立网络接口和路由。取消登录只终止本次登录命令，不退出账号或停止系统服务。

### 安装与系统服务引导

没有安装或系统服务不可用时，点击“检查 Tailscale 安装方案”。先查看当前节点的平台、实际命令、所需管理员权限，以及内置脚本和 SHA-256；勾选确认后才会执行。方案有效期十分钟、只能执行一次；执行前重新检查安装和命令，系统状态改变后需重新审阅。安装不自动登录账号，成功执行命令也不等于已完成系统权限授权或加入 tailnet。

| 平台 | 安装方式 | 已安装但服务不可用 | 限制 |
| --- | --- | --- | --- |
| Debian / Ubuntu 桌面主机 | PolicyKit 授权后，内置脚本添加官方稳定 APT 源并安装，启用 tailscaled | 明确确认后使用 systemctl enable --now tailscaled | 需要 systemd、图形会话和 pkexec；其他发行版转官方指引 |
| macOS | 已有 Homebrew 下载并校验 tailscale-app 官方安装包，核对包签名；macOS 管理员弹窗只授权系统 installer，随后打开应用 | 对已有 /Applications/Tailscale.app 执行 open；CLI 服务提示沿用原系统配置 | 不自动安装 Homebrew，网络扩展仍需用户在系统设置授权 |
| Windows | 使用已有 winget 安装固定软件 ID Tailscale.Tailscale，显示系统授权 | 使用系统 PowerShell 和 UAC 启动现有 Tailscale 服务 | 没有 winget 时转官方下载；不绕过 UAC |
| Docker / Podman 容器 | 不执行主机安装 | 给出容器宿主或已有 Workspace Tailscale 服务的指引 | 不修改宿主网络，不取得额外容器权限 |

安装任务由 Rust 节点持有，关闭网页或窗口不取消。状态记录在 peers.json 旁的私有 tailscale-setup.json，Unix 权限 0600。节点重启后，未完成任务显示 interrupted，提醒检查系统安装器，不自动重放；三十分钟监控超时也不会主动终止系统包事务。输出不写入产品日志；失败显示退出码和恢复指引。没有取消安装按钮，重试前应确认系统安装器已结束。

原本可用的系统 Tailscale 不进行重复安装或服务修改。不会调用 tailscale up/down，不配置子网路由、出口节点或 tailnet ACL；设备间仍需满足 tailnet 策略。安装包可能启用已有后台服务，其网络行为由系统 Tailscale 原配置决定。以上平台适配已实现，但真实管理员弹窗、系统安装及账号登录仍需各平台实机验收。

### 持续发现节点

在 Tailscale 已连接时，填写各设备使用的 Cranibox HTTP 监听端口，点击“启用持续发现”。支持 1–8 个不同端口，用逗号或空格分隔；也能发现同一设备上使用不同端口的多个节点。配置保存在本节点私有的 networks.json；关闭页面后仍在后台检查，重启节点后自动恢复。旧的单端口配置及 `port` API 继续兼容，新界面使用 `ports` 数组，空数组停止发现；重复、越界或超过 8 个端口的配置不会覆盖原状态。

每轮仅检查当前在线、地址唯一的标准 tailnet 成员，最多 128 台，全部端口共用最多 8 个并发请求；每台的每个指定端口最多尝试一个 IPv4 和一个 IPv6 地址，只请求只读身份接口，不探测未填写的端口。身份请求不携带凭据，沿用 2 秒及 4 KiB 限制。完成后等待 30 秒再检查；配置或在线成员列表发生变化时取消旧轮并重新发现。端口和设备较多时一轮会更长。后台每 3 秒读取系统 Tailscale 状态，断开或状态不可用时清除旧结果并等待恢复。当前使用系统状态中最多 512 台可见设备；超过单轮上限时显示未检查数量。

列表展示最近完成时间、已检查设备数量和完整 NodeID。同一设备的多个端口返回相同 NodeID 时合并为一张卡片，可选择连接地址，优先顺序遵循配置而不是响应速度；不同设备返回相同 NodeID 时隐藏这些冲突身份，不替用户选一个。本机身份也不会列出。结果是最近一次观察，不保证下一次连接仍然可达。点击“接入节点”后仍需填写目标访问 Token；保存前重新核对实时在线成员和 NodeID，不会因为发现结果自动授权、保存连接或替换已有路径。点击“停止发现”清除发现结果及后台恢复设置，保留此前明确保存的设备连接。

### 查找并接入节点

1. 在目标 Cranibox 的“入站授权”开启能由 Tailscale 地址访问的节点 HTTP 监听；仅绑定回环地址的监听不能接受其他设备连接。记录实际端口，并为调用方的 NodeID 签发所需权限。
2. 调用方在 Tailscale 在线设备旁点击“查找节点”，选择目标地址，填写节点监听端口，点击“核对节点身份”。界面展示目标的完整 Cranibox NodeID；查找过程不携带目标访问 Token，也不自动扫描其他设备或端口。
3. 核对 NodeID 后填写目标访问 Token 并保存。Rust 后端重新读取 Tailscale 在线状态和目标身份，身份变化或离线时拒绝保存。成功后可在共享直连列表检查能力、执行命令、打开终端和桌面；不依赖 Workspace 网关。

查找只接受系统 Tailscale 实时列出的在线成员，以及标准 Tailscale IPv4/IPv6 地址，不接受主机名、子网路由地址或自定义地址池。每次身份 HTTP 请求限 2 秒、4 KiB，不跟随重定向或使用 HTTP 代理。HTTP 在既有 tailnet 通道内传输；目标授权依然单独验证，不提供额外的公钥配对或证书固定。

此入口可添加新设备，也可为已有相同 NodeID 的设备增加路径。已有设备必须使用相同的目标访问 Token，不替换凭据或覆盖其他路径；重复接入同一地址为幂等操作。EasyTier 与手动路径也遵循同一授权约束。可在“直连设备 → 连接路径”调整优先顺序、增加地址或移除备用路径。网络成员身份本身不授予能力，查找完成也不代表已取得目标授权。连接保存到现有私有 `peers.json` 和 Token 文件，重启保留；查找表单和 Token 不进入浏览器存储，刷新不会自动重新执行查找或保存。

## 当前边界

这是对等组网的第一阶段，使用现有 v1 节点能力协议。EasyTier 发现信息使用短哈希提示和公开的只读 NodeID 身份接口，避免上游 32 字符设备名限制；它不是公钥身份、证书固定或密码学配对。网络成员应是可信设备，知道网络 Token 的成员可以提供伪造的发现信息，因此目前不适合把未知成员加入同一网络。目标能力仍分别验证目标访问 Token。

签名节点目录、公钥配对、Tailscale 能力广播、既有连接的无缝迁移、全网目录自动分发、离线编辑和跨设备运行中 Agent 迁移仍待实现。已接入授权设备的项目目录支持增量读取、只读离线快照和明确启用的后台同步，见[项目与会话目录](project-session-catalog.md)。短期邀请完成网络配置的引导，不提供节点的密码学配对；多入口仅解决 EasyTier 的重新入网，不表示已有 TCP 连接可以无缝迁移。整体设计见[对等组网设计](decentralized-node-network-design.md)。

## 验证

系统安装引导另有四项 Rust 夹具测试，覆盖未审阅不执行、方案 ID/过期/系统变更、单次执行、失败后的状态持久化、写盘失败不启动及重启不重放；夹具只运行临时目录中的无害 Shell，不调用真实包管理器。网络 API 验证认证、CSRF、同源、拒绝任意程序/下载 URL、已有可用服务不修改和容器拒绝主机安装。共享 UI 验证确认、错误恢复、刷新与重进、过期、官方外链、明暗、小屏、横屏、减弱动画及大字号；Tauri 使用模拟 IPC。各系统真实安装与管理员授权仍待实机验收，见[收尾记录](remote-workspace-validation-2026-10-18.md#tailscale-安装引导收尾)。

Rust 测试覆盖配置校验、发现去重与身份匹配、下载校验和安全解压、Tailscale 状态脱敏，以及邀请的哈希保存、过期、网络绑定、单次领取、撤销和地址限制。Tailscale 查找及持续发现另验证在线成员限制、IPv4/IPv6、响应大小和版本、禁止重定向、不发送凭据，以及已有连接与 Token 的原子保护。持续发现另覆盖不安全地址排除、身份冲突、地址回退、后台扫描、显式停止、私有设置持久化及无页面请求时的重启恢复。`tests/test_device_networks.py` 通过真实 Rust Web API 验证认证、CSRF、同源限制、私有配置、正常退出与重启恢复、两个 Workspace 的邀请接入和失败前置检查，以及在线状态变化后拒绝查找，使用隔离的进程替身，不改动系统网络服务。Web 与 Tauri 浏览器测试覆盖安装确认、表单保留、邀请、后台状态、授权、登录链接、Tailscale 逐设备查找与身份变化、页面重进和移动布局；Tauri 测试使用模拟 IPC。真实 Tailscale 设备间的 ACL、监听与连接仍需实机验收。

额外的真实 EasyTier 测试使用官方固定版本的程序。双节点用例验证双向发现、错误 Token 拒绝、授权命令、节点重启恢复、原远端 Shell 保持及明确断开。三节点用例关闭首个入口，再重启第三台设备，验证它通过另一个普通成员重新接入、恢复目标授权与稳定转发、继续使用原 Shell 和执行新命令：

~~~sh
CRANIBOX_TEST_EASYTIER_DIR=/path/to/easytier-linux-x86_64 \
  cargo test --locked -p cranibox-node network::tests::real_ -- --ignored --nocapture --test-threads=1
~~~

需要允许创建网络套接字。该测试不创建 TUN、不连接宿主 Docker，也不安装系统服务；当前实际运行验证是在 Linux，Windows/macOS 的真实网络、托盘、权限与安装包体验仍需对应平台验收。
